## Research

- **2026-09-25 Level extractor and level catalog**: all 150 levels are decoded from the disk data and shown in Chapter 6 of the HTML research browser as the level editor shows them. Input are XekriRedmane's track files in `reference/lode_runner_reveng/disk/`, not the `.do` image: they are committed, so the Pages build can regenerate everything, while the disk image is local only. Three scripts, each with its own tests: `scripts/level_extractor.py` parses the track files and decodes a level with the contract in `docs/main-nw/06-levels.md`; `make level-ascii LEVEL=N` prints it as an ASCII map, `make level-check` reports players, guards, gold and exit-ladder cells per level, plus the problems it finds. `scripts/level_images.py` draws each level as a PNG with the game's sprites 0 to 9, which are also the stored cell values, so trapdoors and hidden exit ladders are visible (`make level-images`, into `images/levels/`; Pillow is a new dependency). `scripts/level_catalog.py` writes linked thumbnails, five to a row, between `<!-- level-catalog: begin -->` and `<!-- level-catalog: end -->` in `research/main.nw-edited.md` (`make level-catalog`); `replace_between_markers` in `scripts/sprite_tables_to_html.py` now takes the markers as parameters, and `scripts/web/style.css` has a `.level-catalog` block (noted in `scripts/PROVENANCE.md`). Findings: every level has exactly one player and only cell values 0 to 9. Levels 8, 80 and 113 have six guards on the disk; `DRAW_LEVEL_PAGE2` removes every guard after the fifth (`CPX #5`), and because it scans backwards from row 15 and column 27, the removed guard is the topmost one (the leftmost, if the topmost row has several). Code-confirmed; Observed for level 8 in AppleWin and on the vgmaps.com panels, which are made from in-game screenshots. After level 150, track `$0C` holds sectors its file header calls "leftover mastering data": three plausible levels (152 to 154), a sector with an ascending test pattern (155) and a garbled one (160); `level-check` lists them for information only. Sprites 0 to 9 use only the first 10 of their 14 columns (checked), so a cell is 10 x 11 pixels and a level 280 x 176, the width of the hi-res screen. XekriRedmane coloured each sprite on its own, which leaves a black pixel column where two blue cells meet; the images fill a single black pixel between two blue or two orange ones, as the TV does (Inferred from the colour model; a test checks that no such gap occurs inside the sprites). PNGs carry no timestamp, so unchanged levels regenerate byte-identical: after the gap fill, level 14 was the only image git saw unchanged, as the only level without bricks, solid blocks or trapdoors. Two annotations in Chapter 6: the catalog after the chapter's opening sentence, and the six-guard finding with the level 8 image after the `.check_for_guard` chunk. A search with Gemini found no published catalog of all 150 levels as the editor shows them, with trapdoors and hidden ladders; the collections that exist are made from in-game screenshots.

- **2026-09-22 Chapter 3 annotated with the `a2-hires-lab` findings**: three annotations in `research/main.nw-edited.md`, each a blockquote marked `` **(`a2-lode-runner`):** ``. In 3.1: the two example sprites are sprite 9, the player (`SPRITE_PLAYER` = `$09`), and sprite 87, the letter S (between R and T in the catalog; `a2-hires-lab`'s README calls it "5"-shaped); colour depends on odd or even screen columns, shown with `images/player_orange_blue.jpg` from `a2-hires-lab` (own work, no provenance entry; the caption explains grey as black and the green square as the selected Excel cell where the sprite was placed); pointer to Jeffrey Stanton, *Apple Graphics & Arcade Game Design* (The Book Company, 1982). In 3.2: why the sprite table is stored as 22 blocks of 104 bytes (no multiply instruction; the sprite number is the index), and where to look up pixels in the workbook. In 3.3, after `COMPUTE_SHIFTED_SPRITE`: the two-stage lookup with a worked Mermaid example (pattern `$16`, shift 3 -> `$A95A` -> `$B0 $81`), the equivalent direct 1,792-byte table with its four-line lookup, 1,024 bytes and 616 cycles saved (1,824 -> 1,208 per call, 162 -> 106 per row), and why `main.pdf` lists both tables as "never used" (reached only through self-modified addresses). Checked in the session: equivalence for all 896 pattern/shift cases against the `.asm` tables, all 512 pattern entries used, the example values, and the cycle counts recounted from the code; the direct table itself has not been built or run. New `docs/main-nw/03-graphics.md`: status, findings with evidence labels, open questions (effect on game speed, why two tables, masking in `DRAW_SPRITE`), links; explicitly Apple II implementation research, not an input to the Core Game Spec.

## Planning and project organization

- **2026-09-21/22 HTML research browser published on GitHub Pages** (<https://fschuhi.github.io/a2-lode-runner/>): new GitHub Actions workflow `.github/workflows/pages.yml` -- on every push to `main` (or by hand via "Run workflow") a fresh Ubuntu runner installs Python 3.12, runs `make test`, then `make nwhtml`, and publishes `research/build/` to Pages; failing tests keep the old site online. Verified beforehand that `make nwhtml` runs unchanged on Ubuntu 24.04. Free for public repositories on standard runners; repository setting Pages -> Source: "GitHub Actions". Attribution: the start page (text between the document title and chapter 1 in `research/main.nw-edited.md`) credits XekriRedmane and Doug Smith, links both repositories and `ultima1_reveng`, states the CC BY-SA 4.0 license, and introduces the marker for our additions to Xekri's text, a blockquote starting with `` **(`a2-lode-runner`):** `` (conversions of form, such as LaTeX tables to Markdown, are not marked); every page carries a footer with credit and license (`PAGE_TEMPLATE` in `scripts/weave_html.py`, recorded in its NOTE header and `scripts/PROVENANCE.md`). Images: all seven `\includegraphics` lines became Markdown images; four screenshots made in AppleWin (`title-screen`, `screen`, `iris`, `digging`) and Xekri's two diagrams (`read_joystick_for_command`, `lode_runner_game_loop`, recorded in `reference/lode_runner_reveng/PROVENANCE.md`) live in `images/`; a `main img` rule in `scripts/web/style.css` shrinks images to the reading column. `README.md`: "Read it online" link under the summary, publishing described, screenshots exception in the licensing sentence. Session tooling: `make patch` applies all `*.patch` files in the repo root after a `git apply --check` and moves them to `tmp/applied-patches/` (undo with `git apply -R`); `*.patch` is ignored by git. Tested: several independent patches apply in one call, a patch that builds on another one only applies separately, and without the check first a failing patch leaves earlier ones applied.
